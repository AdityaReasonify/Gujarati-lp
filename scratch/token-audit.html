LLM Orchestration · Token Efficiency Audit

Where the tokens go

A lossless optimization analysis of the gujarati-lp chapter pipeline, measured against 135.9 million input-side tokens of real orchestration traffic.

Scope std-6, 15 chapters × 14 agents Baseline wf_25fbb63d-8b6, 32 agents Method agent transcript usage records Date 22 Aug 2026

01

Executive summary

This pipeline is not badly tuned. Its cache-hit rate is 92.2%, its schemas are already terse, its intermediate results are already minimal, and its model routing is already correct. Anyone looking for sloppy prompt hygiene will not find much.

The waste is structural, and it sits in three places: every agent builds its own cache prefix from scratch, every agent is handed the same 84 KB of policy documents regardless of whether its spec cites them, and the chapter is rasterised and re-read as images far more often than the work requires.

135.9Minput-side tokens, 32 agents
51.4%of billable input is cache writes
2 of 14specs cite the 16k-token anchor bank
15–22%projected lossless reduction

The governing mental model: a token loaded into an agent early costs 1.25× to write into cache, then 0.1× again on every subsequent turn. At the observed 44 turns per agent, one early token costs about 5.6× its size. Everything below follows from that multiplier.

Six optimizations are recommended. None removes a capability, shortens an output, weakens a safeguard, or introduces ambiguity. Four are pure re-plumbing — the same bytes reach the same model, delivered once instead of repeatedly. One removes a verified byte-for-byte duplicate file. One replaces re-derivation with deterministic preprocessing.

A working implementation is included in §10 and has been written to scratch/chapter-runner-optimized.js.

03

Primary sources of overhead

A. Every agent creates its own cache prefix

The shared prompt builder opens with "Run context: std 6, chapter 3…" — chapter-specific text at token zero. Prefix caching matches on an exact leading byte sequence, so two agents that share 95% of their instructions still share zero cache. With ~255 agents in a full std-6 run, the invariant preamble is written into cache 255 times.

B. Context is broadcast, not routed

The prompt orders every agent to read four policy documents in full. Cross-referencing that against what the specs themselves cite:

DocumentTokensSpecs citing itForced on
gujarat_cultural_anchors.md16,0532 of 14all 14
teaching_voice_gu.md9,3712 of 14all 14
author.md3,5440 of 14all 14
global_content_rules.md1,1305 of 14all 14
no_hallucination_policy.md6487 of 14all 14

A pagination agent that counts page boundaries is handed 16,053 tokens of festival and folk-craft anchors. A textbook-ordering agent receives the full child-facing voice calibration. And this just got 92% worse: the mandatory set grew from 43,766 B to 84,193 B when the anchor bank landed, so every future agent pays nearly double what the measured run paid.

C. Chapters are rasterised per-agent and read as pixels

Each agent renders its own private copy of the chapter into run-s6c1-<n> and reads the PNGs itself — 364 image reads across 32 agents. Images are the most expensive input this pipeline handles. Yet A1's entire purpose is producing 00_chapter_normalized.md, the authoritative verbatim transcription. Most downstream agents need that text, not the pixels it came from.

D. A verified byte-for-byte duplicate

04_converged.json is byte-identical to 02_structure.json in all three completed chapters — 17,420 B, 34,325 B and 31,407 B respectively, confirmed with cmp. A4 spends output tokens re-emitting a file that already exists, and every downstream reader carries the duplicate.

E. Re-derivation of already-resolved facts

_genre_index.md was read 12 times and individual genre profiles 11 times each, to re-resolve a genre A1 had already diagnosed and recorded in 01_meta.json.

04

Recommended lossless optimizations

O1

Invariant-first prompt ordering

High impact

Current source of usage

10,599,011 cache-creation tokens across 32 agents. base() interpolates ${ch}, ${chDir} and ${pdf} into its opening sentence.

Why it is inefficient

Prefix caching requires an exact leading byte match. Variable text at position zero guarantees every agent misses every other agent's cache, so a preamble that is 95% identical is paid for in full ~255 times.

Exact change

Split the prompt into a byte-identical INVARIANT constant (constitution, concurrency rules, resume rules, output contract) followed by a variable tail (chapter, paths, spec, routed documents). Nothing in the invariant block may name a chapter or path.

Why it is lossless

Identical bytes reach the model; only ordering changes. The preamble contains no forward references — no instruction depends on having read the run context first. Instruction hierarchy is strengthened: the constitution now precedes task detail rather than trailing it.

Implementation risks

Low. The one hazard is accidentally leaving an interpolation in the invariant block, which silently reverts the benefit. Guard with an assertion that the constant contains no ${.

Validation

Compare cache_creation_input_tokens per agent before and after. Expect a large first-agent write followed by near-zero writes for the invariant portion.

Estimated saving

8–12M billable units per full std-6 run.

O2

Tiered context routing

Highest impact

Current source of usage

30,746 tokens of policy documents delivered to all 14 agents × 15 chapters, amplified ~5.6× by re-reads.

Why it is inefficient

Twelve of fourteen specs never cite the anchor bank or the voice document. The blanket clause was correct when the mandatory set was small; at 84 KB it is the single largest line item in the run.

Exact change

Replace the blanket clause with a per-spec NEEDS map. Tier 0 — no_hallucination_policy + global_content_rules — goes to every agent as a floor. author.md goes to the seven authoring agents. Voice goes to A12 and A16. The anchor bank goes to A9 and A12.

Why it is lossless

Every agent still receives, in full, every document its spec requires. The safety floor is never routed away. The agent is told explicitly: if your spec cites a document you were not given, say so in notes and stop — turning a silent omission into a loud, auditable failure.

Implementation risks

Moderate, and the only recommendation here carrying real quality risk. An agent may depend on a document it never names. Mitigate with the stop-and-report clause plus a control-chapter output diff before committing.

Validation

Run one chapter under both configurations. Diff every artifact. Any semantic difference in authored prose blocks the change for that agent; re-add the document and re-test.

Estimated saving

≈19M billable units per full std-6 run.

O3

Convergence record instead of a structure copy

Medium impact

Current source of usage

A4 writes 04_converged.json as a byte-identical copy of 02_structure.json — up to 34,325 B of output tokens per chapter, then re-read by up to six downstream agents.

Why it is inefficient

Output tokens are the most expensive class in the pipeline, and this output carries no information that is not already on disk.

Exact change

A4 emits a convergence record — {converged, source, sha256, verdict, notes} — and downstream agents read 02_structure.json for structure and 04_converged.json only to confirm convergence.

Why it is lossless

No structural information is lost: it remains in 02_structure.json, unmodified. Auditability improves — the sha256 pins exactly which structure passed validation, which the current copy only implies.

Implementation risks

Low, but touches every downstream spec that names 04_converged.json as an input. Those specs must be updated in the same change.

Validation

Assert the recorded sha256 matches 02_structure.json on disk; confirm QC (A13) still passes on a control chapter.

Estimated saving

≈150k output tokens + ~2M input units per run.

O4

Render once; read text unless pixels are required

High impact

Current source of usage

364 PNG reads and 261 Bash calls across 32 agents; each agent rasterises its own private copy.

Why it is inefficient

Rasterisation is deterministic — identical inputs, identical outputs, zero model judgment — yet it is paid for per agent. Images then enter context at the highest per-unit cost of any input type.

Exact change

Two parts. (a) The Sonnet setup step renders the chapter once into a shared _renders/ directory and verifies the page count. (b) Only A1, A5 and A11 — transcription, verbatim cross-check, pagination — read pixels by default. Others read 00_chapter_normalized.md, with pixel access still available on demand and a required note when used.

Why it is lossless

The renders are byte-identical whoever produces them. 00_chapter_normalized.md is by design the authoritative verbatim transcription of those exact renders — that is the artifact's entire purpose. Agents that genuinely need layout retain full access.

Implementation risks

Moderate. An agent may have depended on visual layout without declaring it. The on-demand escape hatch plus the mandatory note makes any such dependency visible in the run record rather than silent.

Validation

Grep run notes for pixel escalations. Any agent that escalates on every chapter should be promoted to pixels: true permanently.

Estimated saving

≈6M billable units per full std-6 run.

O5

Pre-resolved genre profile paths

Medium impact

Current source of usage

_genre_index.md read 12×, individual profiles 11× each, across a 533 KB profile corpus.

Why it is inefficient

A1 already diagnoses the genre and records active_genre_profiles in 01_meta.json. Every later agent re-opens the index to convert that name back into a path — re-deriving a fact already computed.

Exact change

Setup reads 01_meta.json, resolves each active profile to an absolute path, and the orchestrator injects those paths into the variable tail with an explicit instruction not to consult the index.

Why it is lossless

The same profile files are read in full; only the lookup step is removed. The resolution is A1's own diagnosis, not a new judgment.

Implementation risks

Low. On a resume where 01_meta.json does not yet exist, the list is empty and agents fall back to the index — the current behaviour, preserved.

Validation

Confirm active_genre_profiles in 01_meta.json matches the injected paths; confirm no agent reads _genre_index.md after A1.

Estimated saving

1–2M billable units per run.

O6

Cache-window-aware group scheduling

Low impact

Current source of usage

Chapter groups run sequentially. A 15-chapter run spans many hours against a 1-hour cache TTL.

Why it is inefficient

Once O1 lands, the shared invariant prefix is a valuable cache entry. If a group gap exceeds the TTL, it is rewritten from scratch.

Exact change

Keep group cadence inside the TTL by holding 3-way concurrency, and avoid long orchestrator-side pauses between groups. Do not raise concurrency to chase this — 5-way caused 429 starvation.

Why it is lossless

Pure scheduling. No prompt, agent, or output is altered.

Implementation risks

Very low, provided concurrency is not raised. Rate-limit starvation costs far more than a cache re-creation.

Validation

Watch cache_creation_input_tokens at each group boundary; a spike means the window lapsed.

Estimated saving

0.5–1M units, entirely dependent on O1.

07

Risk and quality protection

Five of six recommendations carry negligible quality risk because they change delivery mechanics, not content: the same bytes reach the same model at the same reasoning effort. O2 is the exception and deserves the scrutiny.

The one real risk

Routing is only lossless if the routing table is right. A spec may depend on a document it never names — the anchor bank shapes tone, and a pitfalls agent might reasonably want it without citing it. Three protections:

  • A stop-and-report clause. Agents are told to halt and report rather than guess if a cited document is missing. A routing error becomes a loud failure, never silent degradation.
  • A conservative floor. The no-hallucination policy and global content rules go to every agent unconditionally. No safety document is ever routed away.
  • Generous initial tiers. author.md goes to all seven authoring agents despite being cited by none, because it is the pack's constitution. Tighten only on evidence.

Explicitly not recommended

  • No summarizing or truncating policy documents. Verbatim rules must reach the model verbatim.
  • No model downgrades. Routing already matches the standing policy — Opus authors, Sonnet handles mechanical steps, Fable does QC only.
  • No schema trimming. The three schemas total under 400 tokens and carry the run's structured observability.
  • No reduction in reasoning effort. A12 stays at xhigh.
  • No concurrency increase. 5-way caused 429 starvation; the cost of rate-limit thrash exceeds every saving here.
  • No dropped retry or QC paths. The A4 revalidation loop and the A13 owner-rerun gate are untouched.

08

Validation and benchmarking plan

Chapter 4 (આવ્યો મેહુલો) is the natural control: queued, untouched, and a poem, so it exercises genre profiles, verbatim transcription and authoring together.

  1. Establish the baseline. Run ch04 unmodified. Archive every artifact and the per-agent usage totals.
  2. Run the optimized pipeline on ch05, then on ch04 into a scratch directory for a like-for-like comparison.
  3. Diff the artifacts. Structural JSON must match on keys, counts and ordering. Authored prose will not match token-for-token — compare on block count, word-band compliance, one-example-per-scene, and anchor presence.
  4. Gate on QC. A13 must return pass with no new blockers, and LP2 validation errors must not increase.
  5. Read the escalation notes. Any agent escalating to pixels or reporting a missing document identifies a routing table entry to correct.
  6. Compare usage. Expect cache creation per agent to fall sharply; total reads to fall proportionally to routed-away context.

Success criteria. Equal or better QC and LP2 outcomes, no reduction in authored block counts, no new hallucination or verbatim findings, and a measured drop in billable input units. Any authored-quality regression blocks the change for the agent responsible — not for the whole roadmap.

10

The optimized pipeline

A complete implementation of O1–O5 is written to Gujarati-lp/scratch/chapter-runner-optimized.js (14,474 bytes, syntax-checked). It preserves every behaviour of the current runner: resume-awareness, the A2→A4 validation chain with its single re-run, A11 running parallel to that chain, the A13 QC gate with owner re-runs, LP2 validation, batch-state updates, and the group-failure circuit breaker.

The load-bearing change

// ── O1: INVARIANT PREFIX ──────────────────────────────────────────
// Byte-identical for every agent of every chapter, so one cache entry
// serves the whole run instead of ~255 separate cache-creation events.
// Nothing here may reference a chapter, a path, or a spec.
const INVARIANT = `You are executing ONE agent of the gujarati-lp pipeline.

CONSTITUTION — these outrank every instruction that follows.
- Never fabricate. [] and null are correct answers.
- Verbatim Gujarati is TRANSCRIPTION from page renders, never recall.
- Write ONLY your own declared output files...
- Page renders are provided already rasterised. Do NOT re-run pdftoppm.

CONTEXT ROUTING: you are given exactly the policy documents your spec
requires. If your spec cites a document you were not given, say so in
notes and stop rather than guessing at its contents.`

// ── O2: TIERED CONTEXT ROUTING ────────────────────────────────────
